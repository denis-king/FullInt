# FullInt on every platform: against GMP (C++) and BigInteger (.NET)

2026-11-27, one run per platform, the same commit. A word is 64 bits; the operands are random, `div` /
`mod` a 2N-word dividend by an N-word divisor; each cell the minimum over the rounds.
- **Windows** (x64 and x86): AMD Ryzen 7 7730U (Zen 3), Windows 11, MSVC 19.5x, GMP 6.3 (vcpkg);
  .NET 10.0. The machine was not idle (about 19% background load: the small sizes carry a few
  percent of noise - a repeat of the .NET `todec` row at 2-4 words gave 1.06-1.08 where this run has
  0.88-0.98).
- **ARM64**: Oracle Ampere A1 (Neoverse-N1), one core of a container (`--cpuset-cpus=1`), Ubuntu
  24.04, GCC 13, GMP 6.3; .NET 10.0.
- **ARMv7** (32-bit): the same machine running AArch32 code natively, an armhf container; .NET up to
  4096 words (BigInteger's `todec` at 16384 takes minutes there).

C++: `FullInt.Cpp/bench/api_vs_gmp.cpp` (`fullint_bench_api --ops ... --max 16384`). .NET:
`FullInt.Benchmarks cross` (both libraries warmed up on every operation and size, with pauses for the
JIT, before measuring).
